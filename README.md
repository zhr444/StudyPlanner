# 📚 StudyFlow — Система управления учебными задачами и дедлайнами

**Курсовой проект: единое веб-приложение для студентов и учебного отдела.**

Приложение объединяет функции планировщика задач (вдохновленного Todoist и Notion), интерактивного календаря с расписанием чётной и нечётной недель, автоматических напоминаний о дедлайнах и формирования отчётов об успеваемости в форматах XLSX и PDF. 

Проект реализован как классическое full-stack приложение: серверная часть на **C# (ASP.NET Core 8.0)** с базой данных **PostgreSQL 15**, а клиентская часть — SPA на чистом **HTML5, CSS3 (Tailwind) и JavaScript**, работающая в папке `wwwroot`.

---

## ✨ Возможности

Приложение поддерживает три роли пользователей с разным уровнем доступа:

### 🎭 Гость (Неавторизованный пользователь)
- Ознакомление с возможностями системы и пошаговой инструкцией.
- Переход к формам входа (студент / администратор) и регистрации.
- Переключение светлой/тёмной темы и языка интерфейса (RU/EN).

### 🎓 Студент
- **Интерактивный дашборд**: карусель ближайших дедлайнов, сетка расписания на текущую неделю и список приоритетных задач.
- **Мои задачи**: создание, редактирование и удаление задач (лабораторные, практические, курсовые). Фильтрация по статусу, приоритету и дисциплине.
- **Календарь**: режимы «День / Неделя / Месяц». Цветовая дифференциация задач по срочности или по учебным дисциплинам.
- **Расписание занятий**: переключение чётной/нечётной недели, привязка сдачи конкретной задачи к определённой паре.
- **Отчёты**: выгрузка ведомости успеваемости за выбранный период в **XLSX (Excel)** или **PDF**, просмотр истории экспорта.
- **Личный кабинет**: редактирование ФИО, контактов, смена учебной группы и пароля.
- **Напоминания**: счётчик уведомлений, модальное окно со списком дедлайнов (за 3 дня, за 24 часа, в день сдачи).

### 🛡️ Администратор
- **Мониторинг пользователей**: таблица студентов с активностью по задачам (сдано / в работе / просрочено).
- **Управление аккаунтами**: блокировка/разблокировка студентов (с указанием причины), сброс пароля доступа, корректировка учётных записей.
- **Справочники**: CRUD-операции для дисциплин, преподавателей, учебных групп и базовой сетки расписания.
- **Системные записи**: просмотр и корректировка всех задач в системе, восстановление исходных записей БД (сброс демо-данных).

## 📁 Структура проекта

Проект разделен на серверную часть (C#) и клиентскую часть (расположена в `wwwroot`).

```text
StudyPlanner/
├── Controllers/      # API-контроллеры (Tasks, Auth, Admin, Reports)
├── Data/             # DbContext, конфигурации Entity Framework
├── Database/         # SQL-скрипты миграций и инициализации БД
├── DTOs/             # Data Transfer Objects для запросов/ответов API
├── Models/           # Классы сущностей БД (15 таблиц по ER-диаграмме)
├── Services/         # Бизнес-логика (генерация XLSX, планировщик напоминаний)
├── wwwroot/          # Клиентская часть (фронтенд)
│   └── index.html    # SPA-приложение (полный интерфейс и логика)
├── appsettings.json  # Строка подключения к PostgreSQL и настройки
├── Program.cs        # Точка входа в приложение ASP.NET Core
└── StudyPlanner.csproj
```

*Примечание: В текущей демонстрационной версии клиентская часть (`wwwroot/index.html`) полностью автономна и использует `localStorage` для имитации работы серверной БД, что позволяет запускать и проверять интерфейс без развертывания PostgreSQL.*

## 🚀 Быстрый старт

### Вариант 1: Запуск полного стека (C# + PostgreSQL)

1. Убедитесь, что у вас установлен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) и PostgreSQL 15.
2. Настройте строку подключения в `appsettings.json`.
3. Примените миграции к БД (из папки проекта):
   ```bash
   dotnet ef database update
   ```
4. Запустите сервер:
   ```bash
   dotnet run
   ```
5. Откройте в браузере `https://localhost:5001` (или порт, указанный в консоли).

### Вариант 2: Запуск только клиентской части (Демо)

Если вы хотите посмотреть на интерфейс без развертывания бэкенда:

1. Скопируйте файл `wwwroot/index.html` в любую пустую папку.
2. Откройте его двойным кликом в браузере (или через локальный сервер, например `python -m http.server 8000`).
3. Все данные будут сохраняться локально в браузере (`localStorage`).

## 📊 Схема данных (15 таблиц)

Система спроектирована в соответствии с ER-диаграммой:

1. `priorities` — справочник приоритетов (Низкий, Средний, Высокий, Критический).
2. `statuses` — справочник статусов (К выполнению, В процессе, Сдано, Просрочено).
3. `task_types` — типы работ (Лабораторная, Практическая, Курсовая).
4. `reminder_types` — типы напоминаний.
5. `disciplines` — учебные дисциплины.
6. `teachers` — преподаватели.
7. `teacher_disciplines` — связь преподавателей и дисциплин.
8. `groups` — студенческие группы.
9. `group_disciplines` — связь групп и дисциплин.
10. `schedule` — расписание занятий (с флагом чётности недели).
11. `admins` — администраторы системы.
12. `users` — студенты.
13. `tasks` — учебные задачи.
14. `reminders` — запланированные уведомления.
15. `report_exports` — журнал выгрузок отчётов.

## 📐 Особенности реализации

### Экспорт в XLSX
Для формирования Excel-файлов на клиенте используется формат **SpreadsheetML 2003** (открытый XML-формат). Файл собирается на лету из данных задач и скачивается через `Blob` и `URL.createObjectURL`, не требуя подключения тяжелых сторонних библиотек.

### Экспорт в PDF
Реализован через вызов `window.print()` с отдельными CSS-правилами `@media print`, которые скрывают интерфейс (навигацию, кнопки, формы) и оставляют только таблицу с ведомостью успеваемости.

### Локализация (RU / EN) и Темы
Клиентская часть поддерживает мгновенное переключение тёмной и светлой темы (через CSS-переменные и класс `.dark`). Локализация реализована через словарь `RU_TO_EN` и обход DOM-дерева (`TreeWalker`), что позволяет переводить интерфейс без перезагрузки страницы.
